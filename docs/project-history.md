It is not a substitute for Git history and deliberately omits command transcripts, exhaustive compatibility matrices and superseded investigations. Durable rationale lives in [Engineering Decisions](decisions.md); current implementation details live in the topical documentation; unfinished work remains in the [Roadmap](roadmap.md).

## 2026-08-16 — Diagnose the Android gesture-bar band, and change nothing

- **No code changed.** The white band behind the Android gesture bar is a Chromium defect whose fix merged upstream on 2026-08-06 and colours that bar from `theme_color`, already `#080a20` here — so the manifest keeps `display: standalone` and the band should clear itself. Rationale in [D-260816a](decisions.md#d-260816a--wait-for-the-chromium-fix-instead-of-working-around-the-android-navigation-bar), the check to run in the [Roadmap](roadmap.md#performance-seo--platform-polish).
- **The band was introduced by [#134](https://github.com/henetiriki/portfolio/pull/134)**, which switched `display` from `fullscreen` to `standalone` in the same commit that changed `background_color` to `#080a20`. Under `fullscreen` — the behaviour since [#32](https://github.com/henetiriki/portfolio/pull/32) — Android draws no system bars, so there was no navigation bar to mis-paint.
- **[D-260815d](decisions.md#d-260815d--paint-the-document-canvas-on-html-not-on-body) is corrected in place rather than left standing.** It claimed Chrome derives the gesture-bar region from the document canvas — true of a browser tab, false of an installed app. The opaque `html` background is correct on its own merits and stays, but it never addressed the reported symptom, and production serving `html: rgb(8, 10, 32)` with the band still present is what proved it.
- **Two workarounds were built and both discarded.** A revert to `fullscreen` was written, validated and ready to commit; `viewport-fit=cover` was abandoned mid-implementation. Both were dropped once the upstream fix turned out to be ten days old rather than five years — **a permanent workaround for a temporary defect outlives the bug**, because nobody remembers to remove it.
- **The ticket was nearly cited without being read.** An earlier draft referenced [issues.chromium.org/40759522](https://issues.chromium.org/issues/40759522) on the strength of a search-result title, then misread its 2021 filing date as the age of the fix. The tracker needs a sign-in and could not be read by tooling; the owner read it, which is what turned the decision around.
- **A stale roadmap item left behind by [#179](https://github.com/henetiriki/portfolio/pull/179) is removed**: the duplicated-maskable-icons question it described was answered by that change, which split `any` and `maskable` into separate files.

## 2026-08-15 — Repaint the PWA canvas, icons and splash screens

- `html` now carries an opaque `--mantine-color-black-russian-4` background, so the document canvas matches the manifest instead of falling back to the user-agent white. Behaviour in [Styling & Theming](styling-theming.md#the-document-canvas-background), rationale in [D-260815d](decisions.md#d-260815d--paint-the-document-canvas-on-html-not-on-body).
- Every icon and splash asset is regenerated from `public/images/ouwl.svg`, whose fill was inverted black to white so it matches the header logo. Rationale in [D-260815e](decisions.md#d-260815e--generate-the-pwa-icon-and-splash-set-from-one-vector-master), current shape in [PWA & SEO](pwa-seo.md#progressive-web-app).
- **The white disc on Android was the manifest, not the splash files.** `purpose: any` and `purpose: maskable` shared one pair of files, so `any` resolved to maskable artwork — a black owl on an opaque white square — which Chrome then drew over `background_color`. They are now separate files with different artwork, and a `monochrome` layer was added for Android's themed icons.
- **The splash matrix was stale in both directions.** It carried iPhone 5 and 6 Plus sizes while covering nothing newer than 2022, and because `apple-touch-startup-image` matches an exact device triple, every iPhone since the 14 Pro Max was getting no splash at all. Six device classes added, 30 files to 42, point sizes verified per device.
- **Two things were only found by reading the pixels rather than the rendering.** The old `apple-splash-*` files were on a _transparent_ background, not white — the white came from the viewer compositing them. And `apple-icon-180.png` was a black owl on transparency, which iOS composites onto an opaque ground, so it had been near-invisible on the iOS home screen for years without anyone on Android seeing it.
- **Owl scale is now consistent across orientations for the first time**, at 35% of the short edge. The old set used 0.70 portrait and 0.349 landscape, so the same device got a logo at half size depending on how it was held.
- **The 42 `<link>` tags moved out of `_document.tsx` into `AppleSplashLinks`**, generated from one table of device points and pixel ratios. React 19 hoists them into `document.head` on its own, which the first version of the test did not know — it queried the render container, found nothing, and three of its four assertions passed vacuously over an empty list.

## 2026-08-15 — Stop rediscovering that the shell-hygiene hook refuses prose

- [`AGENTS.md`](../AGENTS.md) now requires commit messages and pull request bodies to be written to a file and passed with `git commit -F <file>` or `gh pr create --body-file <file>`, never an inline heredoc. [D-260814b](decisions.md#d-260814b--enforce-shell-hygiene-with-a-hook-rather-than-a-convention) carries the correction that prompted it.
- **The documented casualty was the rare one.** The hook tests the entire command string, and the limit was illustrated with `find … -exec … \;`, which implied collisions were occasional. A heredoc body is part of that string too, so a single semicolon anywhere in a commit message refuses the commit — and this project asks for long prose messages, so one usually appears. Every new session hit it, diagnosed it, and worked around it identically.
- **The hook was not narrowed, deliberately.** Ignoring text after a `<<` marker would have stayed textual and needed no shell grammar. It was rejected because the Auto-mode revision to the same decision promotes this hook from an ergonomic measure to the control that keeps the allow and deny lists honest, and a heredoc is exactly where an evasion would hide. Writing the message to a file is better practice regardless — reviewable before it runs, for the same reason `Write` beats a heredoc for file changes.
- **`D-260814b`'s stated cost was wrong and is corrected in place** rather than left standing: it claimed parsing would save "a handful of commands a year". The docs describe what is true today, and that sentence had been falsified by use.

## 2026-08-15 — Give documentation-only changes a cheap CI path

- `ci.yml` classifies each change with one `git diff` and gates every expensive step behind it. A change touching only `docs/`, `*.md`, `.claude/` or `.worktreeinclude` installs dependencies, runs `prettier:check` and stops. Behaviour on the [release checklist](release-checklist.md#pull-request), rationale in [D-260815c](decisions.md#d-260815c--give-documentation-only-changes-a-cheap-ci-path-rather-than-no-ci-run).
- **A third of recent runs were buying nothing, measured rather than assumed.** Replaying the classification over the thirty merges to `main` up to [#175](https://github.com/henetiriki/portfolio/pull/175): **ten take the cheap path**, including the two most recent documentation pull requests and the shell-hygiene hook change ([#164](https://github.com/henetiriki/portfolio/pull/164)), which touched only `.claude/settings.json` and `AGENTS.md`.
- **The same replay is what proves the exclusion list is CI's and not Vercel's.** [#173](https://github.com/henetiriki/portfolio/pull/173) takes the full path on `e2e/` alone — the change Vercel skips and CI most needs to run — and [#166](https://github.com/henetiriki/portfolio/pull/166) takes the full path on `.gitignore` alone, which is deliberately in neither list.
- **The job still runs and still reports**, because the filter is a per-step `if:` rather than `paths-ignore`. A filtered-out workflow never reports, and a required check that never reports leaves a pull request pending forever — which would have quietly broken the branch protection the [Roadmap](roadmap.md#testing--automation) plans, before it was ever switched on.
- **`prettier:check` is the one step never gated**, since `prettier .` covers the whole tree and is the only check that applies to a prose change at all.
- **Skipping the Jest run has a consequence for branch protection, now written into the item that owns it.** No coverage report is uploaded, so `codecov/patch` is not expected to post on a documentation-only pull request; requiring it needs checking against a real one first. Nothing is required today, so nothing is broken today.
- **`fetch-depth: 2` is load-bearing.** The default shallow checkout has no `HEAD^` to diff against. The command fails open in that case and in every other — a failure classifies the change as not documentation-only — so the failure mode is a needless full run, the same direction `vercel.json` chose.

## 2026-08-15 — Harden the shell-hygiene controls for Auto mode

- Adopting Auto mode changed what the permission allowlist is worth, so `.claude/settings.json` was revisited: the hook pattern is now `&&|;|[|][|]`, `Bash(git stash *)` is gone from the allow list, and [D-260814b](decisions.md#d-260814b--enforce-shell-hygiene-with-a-hook-rather-than-a-convention) records which of its two original justifications survived. [`AGENTS.md`](../AGENTS.md) carries the widened rule.
- **`||` was blocked because the trigger for blocking it had quietly stopped firing.** The original carve-out said to widen the pattern if `||` ever appeared in practice — but the observer was the permission prompt, and Auto mode does not prompt for allowlisted commands. `||` launders exactly as `&&` does: it matches `Bash(git add *)` in `git add . || <anything>`, and slips past a soft-deny rule that anchors at the start of the command.
- **A character class rather than escaped pipes**, so no backslashes have to survive both the JSON and the jq layer.
- **`git stash` was allowlisted despite `AGENTS.md` forbidding it.** Survivable while a prompt still sat in front of most commands; under Auto mode it is an unreviewed grant for the one operation most likely to lose a concurrent session's work, since the stash stack is shared across worktrees.
- **Hook changes take effect immediately, unlike permission rules.** Verified in the session that made this one — the edited hook refused the very next command carrying `||`, and then refused the commit describing it. `AGENTS.md`'s warning that `.claude/` changes wait for a session restart holds for permission rules only.

## 2026-08-14 — Stop `git -C` from defeating the permission allowlist

- [`AGENTS.md`](../AGENTS.md) gains a shell-hygiene rule against passing `-C <path>` to `git`, and `.claude/settings.json` gains the bare no-argument forms of the four read-only check scripts plus `git check-ignore` and the browser `find` tool.
- **Found from the symptom, not from a review.** Git commands started prompting for approval again, and the allowlist looked untouched because it was — the commands had changed shape. `Bash(git add *)` matches by prefix and never sees `git -C /path/to/repo add`, and the harness's own auto-allow for read-only git reads the token after `git`, finding `-C` rather than `status`. Ten `git -C … status` calls, seven `log`, seven `grep` and five `commit` in one session all fell through to a prompt.
- **The habit came from avoiding `cd`.** The rule that the working directory persists between calls is what makes `-C` pointless, so reaching for it to honour that rule inverts it. Both defeat the allowlist for the same reason chaining does: matching runs against the whole command string.
- **Widening the rules was rejected as the fix.** `Bash(git -C * )` would allowlist `push --force` and `reset --hard` along with everything else, and per-subcommand `-C` variants would double the list to accommodate a habit with no reason to exist.
- **The four check scripts were listed only as `yarn X *`.** That form matches by prefix and needs the trailing space, so a bare invocation may not match — and bare is how they are run: `prettier:check` 11 times, `type-check` 7, `eslint:check` 7, `css-vars:check` 6, none with arguments. The exact forms were added alongside the wildcards rather than widening either.
- Deliberately still absent: `yarn build` and `yarn test:e2e` write output, `eslint:write` and `prettier:write` rewrite files, and `npx`/`node`/`python3` would grant arbitrary code execution. `git push`, `rebase`, `remote` and `worktree` remain prompts by choice.

## 2026-08-14 — Ship the Content Security Policy in Report-Only

- `next.config.js` now sends `Content-Security-Policy-Report-Only` on every route, built from a directive map so each directive reads as a list. `src/pages/api/csp-report.ts` receives the violations, and `src/server/csp/` parses and filters them. See [Security](security.md#content-security-policy) and [D-260814c](decisions.md#d-260814c--ship-the-content-security-policy-report-only-and-accept-unsafe-inline). Promotion to an enforcing header stays on the [Roadmap](roadmap.md#performance-seo--platform-polish).
- **`'unsafe-inline'` is permanent here, for two independent reasons.** `BotIdClient` renders an inline script and accepts no `nonce` prop, and every page under `src/pages` is statically prerendered — no `getServerSideProps` or `getStaticProps` anywhere — so `_document`'s `getInitialProps` never runs per request and a build-time nonce is just a constant. What the policy still buys is `frame-ancestors`, `base-uri`, `form-action`, `object-src 'none'` and the host allowlists, which is what the new spec pins.
- **The header was silently missing for the first three builds, and the diagnosis was wrong twice.** `headers()` uses `source: '/:path*'`, and Next compiles values as path-to-regexp templates when the source carries a parameter — a plausible enough cause that the colons were escaped to `\:`, which "fixed" nothing and would have shipped literal backslashes no browser can parse. The real cause was that the preview server was serving the **main checkout's** stale `.next`, not the worktree's; every measurement until then described a build that predated the change. `e2e/security-headers.spec.ts` now asserts both halves — the header arrives, and it contains no backslash — taking the suite from 60 to 76 specs.
- **`report-to` was tried and reverted, with the evidence recorded.** It supersedes `report-uri` in Chrome, and adding it alongside `Reporting-Endpoints: csp-endpoint="/api/csp-report"` stopped reports arriving at all: the Reporting API needs an absolute endpoint URL and discarded the relative one, while Chrome had already stopped honouring `report-uri`. A clean A/B — reports within three seconds without it, nothing in a minute with it. The parser's unused batch branch was deleted rather than left speculative.
- **`www.google.com` in `frame-src` was observed, not assumed** — a real Report-Only violation from the YouTube embed's own nested frame on `/experience`, which the browser suite cannot see because it stubs YouTube.
- **Extension-injected reports are dropped at the endpoint.** They violate the policy on every page, nothing here can fix them, and they would swamp the only signal the promotion decision rests on.
- **`.gitignore`'s `node_modules/` did not match the worktree symlink.** The trailing slash requires a directory, and Git sees a symlink as a file, so every worktree showed `?? node_modules` — one stray `git add` from committing an absolute path into the repository.
- **Nothing was loading `AGENTS.md` automatically.** There was no `CLAUDE.md`, so a session began with none of the working conventions and only found them by going looking — which this one did, and a session that dived straight into code would not have. A root `CLAUDE.md` now imports `AGENTS.md` and `docs/README.md`, and `AGENTS.md` gained a rule to read the topical doc for the area being changed before changing it. The index rather than the documentation, deliberately: `docs/` is roughly 250KB across 15 files, which would crowd out the work it is supposed to support.
- **First real exercise of `worktree.symlinkDirectories`, and it half works.** Husky, `lint-staged`, the `yarn` scripts, `yarn build` and `yarn test:e2e` are all fine. `yarn dev` is not: Turbopack rejects the symlink (`points out of the filesystem root`) and panics before serving. `yarn install` does not rescue it — Yarn follows the symlink and installs into the main checkout, leaving the worktree's `node_modules` a symlink still. Recorded in [`AGENTS.md`](../AGENTS.md); the consequence for this change is that the policy's behaviour under `next dev` is unverified, and only the production path was measured.

## 2026-08-14 — Document how concurrent branches and worktrees are worked

- [`AGENTS.md`](../AGENTS.md) gains **Working across branches** and **Worktrees** sections. Concurrent branches were already normal here — the [Roadmap](roadmap.md) asks for each item to be its own scoped change — but nothing said how they integrate, so every rebase re-derived the answer.
- **Written from a rebase that went wrong rather than from first principles.** Rebasing the shell-hygiene branch over the fonts branch produced one honest conflict and three silent failures: Git spliced a new decision into the middle of another, left two identical decision headings, and re-applied an identical `.gitignore` rule a second time — none of it marked. Hence the rule that a clean rebase is not evidence, and that the three documentation files are read by eye afterwards.

## 2026-08-14 — Enforce shell hygiene with a `PreToolUse` hook

- `.claude/settings.json` now carries a `PreToolUse` hook on `Bash` that denies any command containing `&&` or `;`. The rule itself is not new — [`AGENTS.md`](../AGENTS.md) has carried it since the permission allowlist was written — but it was advisory, and advisory rules depend on the model remembering them. See [D-260814b](decisions.md#d-260814b--enforce-shell-hygiene-with-a-hook-rather-than-a-convention).
- **The whole point is that the harness runs it, not the model.** The check is one inline `jq` program: silence when the command is clean, a `permissionDecision: "deny"` carrying the reason otherwise, which the model reads and reissues as separate calls. Inline rather than a script under `scripts/`, so there is no path to resolve and nothing to keep in step.
- **Verified as a program, not as a live firing.** Both branches were exercised by piping synthetic hook payloads into the exact stored command — `yarn type-check && yarn test` and `cd src; ls` produce the deny object, `grep -rn foo src | head -5` produces nothing — and the settings entry was validated against the hook schema with `jq -e`. The hook could not be observed firing from the session that wrote it: settings are watched per directory from session start, and this was written in a worktree. It takes effect for sessions started after the merge. **Confirmed live once merged**: `true && true` was refused, with the deny reason rendered as written.
- **Two limits are deliberate**: the test is textual rather than a shell parse, so a literal `;` inside an argument (`find … -exec … \;`) is refused as well, and `||` is not covered. Pipes are untouched.
