## Bug fixes

- [x] **Audit & fix the Google Maps layer regressions.** Done 2026-08-06. Code-reading audit (comparing `Marker`'s and `Polyline`'s call sites in `MapWrapper.tsx`) turned up two confirmed regressions from the vanilla-JS→React port:
  - **Marker drop-in staggering was broken.** `Marker`/`Polyline` both stagger their drop-in animation via `cancelableDelay(idx * order * 100, ...)` — a multiplication, so `idx === 0` always produces a `0` delay regardless of `order`. `Polyline`'s call sites already dodged this (`idx + 1`); `Marker`'s didn't, so the first airport/station/port marker in each group dropped simultaneously instead of staggering. Fixed in `MapWrapper.tsx` by passing `idx + 1` to `Marker`, matching `Polyline`'s existing pattern.
  - **Zoom reset on resize.** `Map.tsx`'s viewport-size effect forced `zoom` back to the breakpoint default on every `width` change, not just initial mount — so resizing the window after the map loaded would silently discard the user's manual zoom. Fixed by tracking initial setup with a ref (`initialZoomSetRef`) so only `minZoom` stays reactive to viewport width after the first render; `zoom` is set once.
  - Both fixes are covered by regression tests in `components/travel/__tests__/` (`Map.test.tsx`'s "does not force zoom again on a later resize", `MapWrapper.test.tsx`'s "never passes idx=0 to a marker").
- [x] **Fix `useDeepCompareEffectForMaps`'s dead custom-equality comparator.** Done 2026-08-07, found while pushing coverage on this hook — line-by-line coverage staying at 0% for the comparator body despite passing tests was the tell. `createCustomEqual` was called with a factory function (`deepEqual => (a, b) => {...}`), which was the correct API for an old `fast-equals` major version but not the installed `fast-equals@5.4.1`, whose `createCustomEqual` takes an **options object** instead. Since a function is also an object, the mismatched call didn't throw — it silently destructured to all-`undefined` options, making the hook fall back to plain structural deep-equal with zero LatLng-awareness. Existing tests didn't catch it because they only compared plain `{lat,lng}` literals, where structural equality coincidentally agrees with the intended `.equals()`-based comparison; the bug only bites real `google.maps.LatLng` **instances**, which expose coordinates via `.lat()`/`.lng()` methods rather than plain properties. Fixed by correctly using `createInternalComparator` (which only intercepts _nested_ property comparisons) plus a wrapper for the top-level entry point (which fast-equals calls directly, bypassing `createInternalComparator` entirely) — both needed, confirmed via `node_modules/fast-equals`'s own source. New tests cover a LatLng-shaped field nested inside a compared dependency object, which the old (broken) implementation would have gotten wrong.
- [x] **Fix a live-`Set` mutation bug in the Google Maps test mock causing a heap OOM.** Done 2026-08-07, found while writing a test for `Map.tsx`'s recursive `zoomMap` animation — the same test area a prior session had abandoned after an OOM crash (previously misattributed to `jest.useFakeTimers()` + `advanceTimersByTimeAsync`). Root cause was actually in `src/utils/test/googleMapsMock.ts`'s `triggerMapsEvent`: it iterated the **live** `Set` of registered listeners via `.forEach()`. `zoomMap`'s recursive `zoom_changed` handler synchronously registers a new listener on that same event as part of running — and `Set.forEach` visits elements added mid-iteration per spec — so the new listener fired immediately in the same synchronous pass, which registered another, which also fired immediately, unboundedly. Real event systems (DOM, Node's `EventEmitter`) snapshot listeners at dispatch time specifically to avoid this; the mock didn't. Fixed with a one-line snapshot (`[...handlers].forEach(...)`) — confirmed safe via a capped-heap (`--max-old-space-size`) reproduction before and after, and a full suite run afterward. This unblocked testing `Map.tsx`'s zoom-stepping animation directly (previously untested, now 100% covered) and was a test-infrastructure bug, not a production one.
