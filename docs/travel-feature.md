# Travel / Google Maps Feature

The `/travel` page renders an interactive Google Map plotting places the site owner has lived, flown, sailed, and taken trains through, plus upcoming trips. It's the most complex feature in the app.

## Data model (`src/fixtures/travel/`)

| File                                     | Exports                                                                                          | Shape                                                                                                                                                                                                                                                                    |
| ---------------------------------------- | ------------------------------------------------------------------------------------------------ | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |

## Rendering pipeline

1. **`pages/travel.tsx`** dynamically imports `MapWrapper` (`ssr: false`, `loading: MapLoader`) inside a `Content` section, with the `Legend` below.
2. **`MapWrapper`**:
   - Sets up an `IntersectionObserver` with `threshold: 0.8` on a sentinel `<Box />` placed after the map — markers/polylines ("`dropMarkers`") only start rendering once 80% of the map is scrolled into view, deferring the (expensive) marker-drop/polyline-draw work until the user actually reaches the map. The observer callback latches that state and disconnects itself, so leaving the viewport does not unmount work that has already started.
   - Always renders the 9 `cities` as `Marker`s immediately (not gated by `dropMarkers`) since they're the primary content.
   - Once `dropMarkers` is true, renders `markerLocations` (airports/stations/ports) and `tripPolylines` (flights/cruises) as `Marker`/`Polyline` children, each flagged `endMarker`/`endTripPolyline` on the very last item in the very last group — these flags are what trigger the "all loaded" dispatches.
   - Also calls `useRailTrips()` to fetch `/api/rail-trips`, decode it into two `TripPaths` groups (solid trips, dotted upcoming trips colored `torch-red`), cache the result in global state, and renders those as `Polyline`s too (flagged `endRailTripPolyline`).
   - Calls `useGoogleMaps()`, which delegates to the shared `loadGoogleMaps()` singleton. The loader configures `@googlemaps/js-api-loader` v2 once, imports the `maps` and `geometry` libraries on demand, and deduplicates concurrent/remount requests. `MapWrapper` shows `MapLoader` while that promise is pending, `MapError` after a failure, and the map tree after success; a failed request may be retried by a later mount.
3. **`Map`**:
   - Instantiates a single `google.maps.Map` on mount, and a single shared `google.maps.InfoWindow` that all markers push content into (only one info bubble open at a time).
   - Applies `mapOptions()` plus a responsive `minZoom` (1 below 768px viewport width, else 2) in an effect keyed directly to the map and viewport width. The starting `zoom` is set from that same default only **once**, on initial setup (tracked via an `initialZoomSetRef`) — a later window resize updates `minZoom` but deliberately does not force `zoom` again, so it doesn't discard a user's manual zoom (fixed 2026-08-06; see [Project History](project-history.md#2026-08-06--runtime-testing-and-ci-baseline)).
   - Clones every child (`Marker`/`Polyline`) to inject `map`/`infoWindow` props once both exist — this is how the imperative Maps SDK objects get wired to the declarative React tree.
   - Once `markersLoaded && railPolylinesLoaded && tripPolylinesLoaded` are all `true` in global state, pans to `aucklandPoint` and steps the zoom in one level at a time (`zoomMap`, 80ms per step, listening for `zoom_changed` between steps) until zoom 4 — the "reveal" animation. With reduced motion enabled it jumps directly to that zoom instead.
4. **`Marker`** / **`Polyline`** are effect-only components (`return null`) that create one stable `google.maps.Marker`/`Polyline` with a lazy state initializer, then configure and clean up that imperative object through effects with explicit semantic dependencies:
   - Staggered entrance: each waits `idx * order * 100`ms before calling `.setMap(map)`, so markers/lines drop in sequence rather than all at once. Since that's a multiplication, `idx` must never be `0` (a `0` delay regardless of `order`) — `MapWrapper.tsx`'s call sites always pass `idx + 1` for exactly this reason (a bug where `Marker`'s call sites passed a raw zero-based `idx`, breaking the stagger for the first item of every marker group, was fixed 2026-08-06; see [Project History](project-history.md#2026-08-06--runtime-testing-and-ci-baseline)). Reduced-motion users get the same content immediately without the stagger.
   - `Marker` drop animation (`google.maps.Animation.DROP`), click → bounce for 2s + open the shared `InfoWindow` with the marker's title/description (rendered as a raw HTML string styled inline), which auto-closes after 5s of being visible. Drop and bounce are omitted under reduced motion; opening the information window is unchanged.
   - `Marker` icon scale responds to `zoom_changed` via `getZoomMarkerWeightExponent` (steps at zoom ≤10/≤16/≤22).
   - `Polyline` path comes from either literal `legs` (`LatLngLiteral[]` → `LatLng[]`) or a Google-encoded `paths[0]` string decoded via `google.maps.geometry.encoding.decodePath` (hence `loadGoogleMaps()` importing the `geometry` library before rendering the map tree).
   - `Polyline` stroke weight responds to `zoom_changed` via `getZoomPolylineWeightExponent` (finer-grained steps at zoom ≤4/8/12/16/20/24), scaling `STROKE_WEIGHT_DEFAULT` (1.25).
   - Both dispatch a `*Loaded: true` action when their `end*` flag item finishes rendering, and `false` on unmount/cleanup (so re-mounting the map — e.g. route away and back — resets the loaded flags and replays the reveal, while `railTripPolylines` stays cached via `reset-markers-polyline-loaded`). Every entrance, bounce, information-window and recursive zoom timer/listener is captured and cancelled during cleanup so no SDK object or loaded state is touched after unmount.

## Rail trips API round-trip

`useRailTrips()` fetches `/api/rail-trips` (which just serves the static `railTrips` fixture as JSON — kept server-side rather than imported directly so it isn't bundled into the client JS eagerly) via `fetcher`. Each attempt has its own 30s `AbortController` timeout, cleared in `finally`; both network and non-OK failures are retried twice with 250ms/500ms backoff, and the final rejection is always an `Error`. It reshapes `{ trips, upcomingTrips }` into two `TripPaths` groups matching the flight/cruise polyline shape, then dispatches `set-rail-trip-polylines` to cache the result in global state so it's only fetched once per session (checked via `railTripPolylines.length` before fetching).

## Environment dependency

The Google Maps JS API key is read server-side from `GOOGLE_MAPS_API_KEY` and re-exposed to the client as `process.env.NEXT_PUBLIC_GOOGLE_MAPS_API_KEY` via `next.config.js`'s `env` block (see [Environment Variables](environment-variables.md)). `src/utils/googleMaps.ts` supplies that value to the loader only when the client-side map mounts. The underlying var name was deliberately left unrenamed (it's already configured under that name in Vercel), so this bridges it to a build-time-inlined `NEXT_PUBLIC_*` name instead of Next's removed `publicRuntimeConfig`/`getConfig()` mechanism.

## Modernisation phases

The migration is intentionally split into parity-preserving releases:

1. **Loader (complete):** replace the archived React wrapper with Google's maintained v2 loader while leaving map options, classic markers, polylines and sequencing unchanged.
2. **Map ID and cloud style:** configure the provisioned Map ID, associate/import the resolved local style in Google Cloud, expose the ID through environment configuration, and verify visual parity before removing the local `styles` option.
3. **Advanced Markers:** replace classic markers and their symbol icons with DOM-backed Advanced Marker content, then restore drop/bounce, information-window, zoom-scaling, cleanup and reduced-motion parity using the new API.
4. **Cleanup:** remove compatibility code and audit `MarkerLegend`, documentation and focused tests against the final implementation.
