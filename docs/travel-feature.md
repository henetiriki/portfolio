# Travel / Google Maps Feature

The `/travel` page renders an interactive Google Map plotting places the site owner has lived, flown, sailed, and taken trains through, plus upcoming trips. It's the most complex feature in the app.

## Rendering pipeline

1. **`pages/travel.tsx`** dynamically imports `MapWrapper` (`ssr: false`, `loading: MapLoader`) inside a `Content` section, with the `Legend` below.
2. **`MapWrapper`**:
   - Uses `useIntersectedOnce(INTERSECTION_THRESHOLD)` (`@hooks`, threshold `0.8`) on the real map wrapper. No marker or polyline component — including cities — mounts until both 80% of the map is in view and `Map` has observed its first `tilesloaded` event. This prevents Advanced Markers and lines appearing over the blank WebGL surface while the vector base map is still drawing. `useIntersectedOnce` is a small generic hook (`src/hooks/useIntersectedOnce.ts`): it latches and disconnects its `IntersectionObserver` after the first intersection, so leaving the viewport does not undo work that has started.
   - Renders `cities`, `markerLocations` (airports/stations/ports), `tripPolylines` (flights/cruises) and fetched rail trips with stable layer IDs plus one shared `onRendered` callback wired to `useLayerCompletion` (`@hooks`). That hook's ref-backed `Set` deduplicates completion without re-rendering the parent for every layer; the `layersRendered` it returns only goes true once every expected ID has reported and the rail-trip request has settled.
   - Calls `useRailTrips()` to fetch `/api/rail-trips`, decode it into two `TripPaths` groups (solid trips, dotted upcoming trips colored `torch-red`), cache the result in global state, and expose an explicit `settled` state. An empty or finally failed request is therefore distinguishable from a request still in flight and cannot leave the camera reveal waiting forever.
   - Calls `useGoogleMaps()`, which delegates to the shared `loadGoogleMaps()` singleton. The loader configures `@googlemaps/js-api-loader` v2 once, imports the `maps`, `geometry` and `marker` libraries on demand, and deduplicates concurrent/remount requests. `MapWrapper` shows `MapLoader` while that promise is pending, `MapError` after a failure, and the map tree after success; a failed request may be retried by a later mount.
   - Wraps that map tree in its own `ErrorBoundary` with `MapError` as its `fallback`, so a runtime crash happening after a successful script load — not just the script itself failing — also degrades to the same message instead of taking the rest of the page down with it. See [D-260825b](decisions.md#d-260825b--nest-errorboundary-inside-mantineprovider-scope-a-second-boundary-to-the-map-and-centre-the-root-fallback).
3. **`Map`**:
   - Instantiates a single `google.maps.Map` on mount with `mapOptions()`, including the vector Map ID. Google does not allow `mapId` to be set or changed after construction, so it deliberately does not flow through the later responsive options effect. A single shared `google.maps.InfoWindow` receives content from all markers (only one info bubble is open at a time).
   - Registers a one-shot `tilesloaded` listener and reports readiness only after the initially visible vector tiles have finished loading. Children are not cloned into the imperative SDK tree before that event, even if a parent accidentally supplies them early; the listener is removed on cleanup. Until then, `MapPlaceholder` (see [Loading placeholder](#loading-placeholder)) sits over `#map` so a visitor sees a blurred map rather than the empty container.
   - Applies a responsive `minZoom` (1 below 768px viewport width, else 2) after the viewport is known. The starting `zoom` is set from that same default only **once**, on initial setup (tracked via an `initialZoomSetRef`) — a later window resize updates `minZoom` but deliberately does not force `zoom` again, so it doesn't discard a user's manual zoom (fixed 2026-08-06; see [Project History](project-history.md#2026-08-06--runtime-testing-and-ci-baseline)).
   - Clones every child (`Marker`/`Polyline`) to inject `map`/`infoWindow` props once the map, shared InfoWindow and initial tiles are all ready — this is how the imperative Maps SDK objects get wired to the declarative React tree.
   - Once `MapWrapper` reports `layersRendered`, uses the vector camera's fractional zoom to ease both centre and zoom over a fixed 2 seconds until it reaches zoom 4 at the city marked `current: true`. The duration is independent of network/rendering speed, the last frame lands on the exact fixture coordinate, and its animation frame is cancelled on cleanup. With reduced motion enabled it moves directly to the same camera target instead.
4. **`Marker`** / **`Polyline`** are effect-only components (`return null`) that create one stable `google.maps.marker.AdvancedMarkerElement`/`google.maps.Polyline` with a lazy state initializer, then configure and clean up that imperative object through effects with explicit semantic dependencies:
   - Staggered entrance: each waits `idx * order * 100`ms before assigning the Advanced Marker's `.map` property or calling the polyline's `.setMap(map)`, so markers/lines appear in sequence rather than all at once. Since that's a multiplication, `idx` must never be `0` (a `0` delay regardless of `order`) — `MapWrapper.tsx`'s call sites always pass `idx + 1` for exactly this reason (a bug where `Marker`'s call sites passed a raw zero-based `idx`, breaking the stagger for the first item of every marker group, was fixed 2026-08-06; see [Project History](project-history.md#2026-08-06--runtime-testing-and-ci-baseline)). Reduced-motion users get the same content immediately without the stagger.
   - `Marker` appends a custom SVG child to the Advanced Marker element rather than using the deprecated `content` property. Since Advanced Markers have no `google.maps.Animation`/`setAnimation()` equivalent, CSS recreates both animations: the entrance uses Google's documented 300ms bounce-drop keyframes (including the landing compression/rebound), and a click bounces for two seconds. The completed drop class removes itself on `animationend`. The shared `InfoWindow` is anchored with the current object-form API and receives semantic heading/paragraph DOM elements rather than an HTML string. Its native Google header provides the accessible top-right close control and Escape handling; the generated button retains its SDK behaviour and 48px target while a narrowly scoped global rule gives its masked X enough contrast against the white InfoWindow. `ariaLabel` and explicit focus-on-open make the dialog discoverable; closing returns focus through the SDK and cancels the otherwise five-second auto-close timer. `gmpClickable`/`gmp-click` plus the marker title preserve keyboard and screen-reader support. Drop and bounce are omitted under reduced motion; opening the information window is unchanged.
   - `Marker` scales its DOM visual in response to `zoom_changed` via `getZoomMarkerWeightExponent` (steps at zoom ≤10/≤16/≤22), with its transform origin and Advanced Marker anchors matching the former SVG symbol's `Point(10, 20)` alignment.
   - `Polyline` path comes from either literal `legs` (`LatLngLiteral[]` → `LatLng[]`) or a Google-encoded `paths[0]` string decoded via `google.maps.geometry.encoding.decodePath` (hence `loadGoogleMaps()` importing the `geometry` library before rendering the map tree).
   - `Polyline` stroke weight responds to `zoom_changed` via `getZoomPolylineWeightExponent` (finer-grained steps at zoom ≤4/8/12/16/20/24), scaling `STROKE_WEIGHT_DEFAULT` (1.25).
   - Every instance reports its own stable layer ID exactly once: a marker after its own 300ms drop `animationend` (or immediately after attachment under reduced motion), and a polyline immediately after `setMap(map)`. Completion is local to `MapWrapper`, replacing the inaccurate structural "last item" flags that could finish while a longer-staggered earlier group was still rendering. Every entrance, bounce and information-window timer/listener plus the reveal animation frame is captured and cancelled during cleanup so no SDK object or completion callback is touched after unmount.

## Loading placeholder

`MapPlaceholder` renders a Maps Static API image, absolutely positioned over `#map` within a shared relative-positioned container, faded out (opacity transition, instant under reduced motion) once `Map`'s `mapRendered` state goes true. It never mounts inside `#map` itself — Google Maps takes ownership of that div's contents on construction, so the overlay has to be a sibling.

- **`staticMapUrl`** (`mapConfig.ts`) is the fixed path `/api/static-map`, not a direct Google URL. `MapPlaceholder` never talks to Google itself; `pages/api/static-map.ts` proxies one fixed 640×400 request (`scale=2` for a sharper decode) at the same centre as `mapOptions()` and zoom 1, server-side, so the Maps API key stays out of client-visible markup entirely rather than sitting in a copy-pasteable `<img>` `src`. See [D-260825c](decisions.md#d-260825c--proxy-the-static-map-request-through-an-api-route-instead-of-a-client-visible-google-url). It rejects query parameters, so only this canonical request can reach Google, and caches the fixed response at the browser and Vercel CDN for a year (`max-age`/`s-maxage`), preventing the public proxy from becoming a request-amplification path.
- **Zoom 1, not the live map's own zoom 2.** The live map is drawn at real viewport width, so zoom 2 (world width `256 × 2^zoom` = 1024px) shows most of the globe there; the static request is capped at 640px wide, where zoom 2 would only cover ~62% of the world before `object-fit: cover` crops the rest. Zoom 1 (world width 512px) fits inside 640px and matches the live map's near-whole-world framing. See [D-260825a](decisions.md#d-260825a--blur-the-real-static-map-for-the-travel-pages-loading-placeholder-on-a-second-raster-map-id).
- **The image is genuinely `filter: blur(12px)`'d, not Next's shimmer-gradient `blurDataURL()` placeholder** used by `FixedBackground`. `transform: scale(1.1)` keeps the blur's edge sampling inside the element; the container's own background (`--mantine-color-black-russian-4`, matching `global.css`'s page background) covers anything the scaled, blurred image doesn't.
- **A second, raster-scoped Map ID** (`GOOGLE_MAPS_STATIC_MAP_ID`, read server-side only by the proxy route) supplies the same published cloud style to the static request — the Static Maps API only accepts raster map IDs, and the live map's own Map ID is deliberately vector (see [Modernisation phases](#modernisation-phases) below).

## Rail trips API round-trip

`useRailTrips()` fetches `/api/rail-trips` (which just serves the static `railTrips` fixture as JSON — kept server-side rather than imported directly so it isn't bundled into the client JS eagerly) via the shared [`fetcher`](state-management.md). Its timeout and retry policy is documented with the shared state. The hook reshapes `{ trips, upcomingTrips }` into two `TripPaths` groups matching the flight/cruise polyline shape, then dispatches `set-rail-trip-polylines` to cache the result (including a legitimate or failure-derived empty array) in global state so it is only fetched once per session. The hook returns both the cached polylines and `settled`; final failure logs only a fixed diagnostic message and settles empty so unrelated map layers can still complete.

## Environment dependency

The travel map uses browser-visible map configuration supplied at build time. Its provider-side restrictions, configuration names, and local setup are maintained privately; see [Runtime Configuration](environment-variables.md) for safe-handling guidance.

## Production smoke check

The regular browser suite blocks Maps deliberately, so a separate scheduled smoke check visits the deployed `/travel` page. It waits for the real Google Maps script, scrolls the map into view, and verifies Google has rendered its map surface without the page falling back to `MapError`. The check runs daily and may also be started manually; it is diagnostic only and does not gate pull requests or deployment.

## Modernisation phases

The migration is intentionally split into parity-preserving releases:

1. **Loader (complete):** replace the archived React wrapper with Google's maintained v2 loader while leaving map options, markers, polylines and sequencing unchanged.
2. **Map ID and cloud style (complete):** the published cloud style is associated with a raster JavaScript Map ID, that ID is supplied at map construction, and the incompatible local `styles` option has been removed. Raster preserves the previous renderer while this styling boundary is verified.
3. **Advanced Markers (complete):** replace classic markers and their symbol icons with accessible DOM-backed Advanced Marker elements, then restore drop/bounce, information-window, zoom-scaling, cleanup and reduced-motion parity using the new API.
4. **Cleanup (complete):** restore Google's native accessible information-window close control while retaining auto-close, share the exact SVG path/colour/scale definitions with `MarkerLegend`, remove the unused type-guards/transpilation compatibility path, and audit documentation and focused tests against the final implementation.

After those parity phases were verified, the Map ID was switched separately from raster to vector. The reveal now uses vector fractional zoom and `moveCamera()` for a smooth, duration-based transition to the current city.
